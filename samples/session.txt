# Sample session

Input is what the user types. Standard error is marked with # stderr.

help
echo hello world
echo "quoted args"
cd /tmp
pwd
cd -
pwd
echo one > /tmp/msh-sample.txt
echo two >> /tmp/msh-sample.txt
cat < /tmp/msh-sample.txt
printf 'c\nb\na\n' | sort | wc -l
false
echo $?
no_such_cmd
echo $?
ls |
echo $?

Notes:
- `cd /tmp` then `pwd` prints the physical directory. On the test machine that is /private/tmp.
- `cd -` prints the directory it returns to.
- `wc` pads its count. The shell does not add those spaces.
- `false` is an external command. `$?` is 1, the status waitpid collected.
- An unknown command exits 127. The next command still runs.
- `ls |` is a syntax error. The shell sets status 2 and stays up.
- `&`, `;`, `&&`, `||`, and `2>` are rejected. They are not part of this shell.

Invalid and boundary cases covered by tests/test_shell.py:

- empty line and a comment line
- cd with no HOME, cd to a missing path, cd to a file, cd with two paths
- cd inside a pipeline, which must not change the shell
- duplicate output redirection
- redirection with no target
- unclosed quote
- `&`, `;`, and `2>`, which are rejected
- a command that is only `> outfile`
- empty input file
- missing input file
- `exit` with a non-numeric argument, which must not quit
- `$?` inside quotes, which must stay the two characters $?
- a pipeline of 31 stages, which checks that pipe descriptors are closed
- a redirect on a middle pipeline stage, which replaces that stage's pipe end
